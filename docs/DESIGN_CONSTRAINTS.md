# 全局设计约束

更新：2026-10-14。适用：这个个人主页的主版本、设计台、独立预览及构建产物。

本文是后续调整的设计基线。用户最新明确反馈优先于本文；本文优先于旧实验、历史交接片段与通用风格示例。修改设计规则时同时更新本文和对应实现，避免只改某个页面。用户于 2026-10-14 授权先发布当前快照作为首个在线版本；这不代表每条文案永久定稿。

## 1. 一个主版本

- **1440 CSS px 是唯一主设计画幅**（页面内容上限仍为 1280px）。先在此画幅判断构图、层级和节奏，其他宽度仅从它派生适配，不作为平行设计方案。
- 只维护当前主版本，不恢复 A/B/C 切换，不从旧 mockup 重新开始。旧方案位于 `design-lab/archive/`，只作历史参考。
- 首页阅读顺序已确认：**姓名 → 个人介绍与联系方式 → 研究品牌与三个关注方向 → News**。DOM、视觉排列和键盘阅读应表达同一顺序。
- Profile/contact 是独立个人信息区；研究品牌不能和个人信息混排。三个方向是 slogan 的具体展开，默认通过三色叠印圆表达交叉关系。
- 1440 主版沿用已选 B：左侧品牌、右侧三色叠印圆；小于 1024px 时圆移到标题下方，小于 640px 时为 160px 图例加三个方向入口。
- 每屏主视觉集中在姓名与人像。其余文字、线条仍服从油墨规则，但不逐块增加粗网、圆圈和大幅错版。
- **Artifacts 保持自己的风格**：各作品原预览与独立编排可以不同，不统一套 Print Labs 卡片，不给所有缩略图再染色。

实现入口：`src/config/main-version.ts`、`src/components/areas/Home.astro`、`src/styles/home-main.css`、`src/client/home-branches.ts`。

## 2. 两墨与纸

主页主体的视觉用墨只来自**蓝墨、朱红墨、两墨叠印、纸**；研究圆允许第三块黄色版（第 14 节），Print Labs 插页胶带的局部黄色例外见第 13 节。不要新增独立黑墨/灰墨来表示正文、日期或分隔线。抗锯齿、纹理和屏幕混合会产生中间像素值，这不是要求把最终截图量化为四个 RGB 值。

| 角色 | 规则 |
| --- | --- |
| 正文、日期、mono 标签 | 蓝墨实色；用字号、字重、行距和位置表达层级，不靠灰色或降 opacity |
| 品牌、区块标题 | 蓝墨主体，可用共享朱红底版叠印；保持完整可读 |
| 当前导航与强调点 | 朱红状态墨；可与蓝墨叠印，不增加新强调色 |
| 正文强调 | 沿用当前正文与蓝墨，以字重强调；不恢复旧网点强调带，不伪装成链接 |
| 链接 | 有明确可点击提示与焦点样式；下划线留给实际链接 |
| 浅色块、次要底形 | 用共享网点覆盖率表达浅墨，不能独立手调一种灰色或透明墨色 |
| 线条与连接关系 | 使用这两种墨；连接必须有实际语义，交叉可出现叠印色 |
| 纸张与颗粒 | 克制，不能妨碍正文；新纸纹不得引入一套额外墨色 |

原始作品图、科研图和素材源文件不受“重染成两墨”的要求；保留其信息和色彩含义。分版/网点诊断视图可以使用专用标记色，但仅在本地开发检查层出现。

## 3. 全页共享的物理参数

“固定”指**同一页每种墨使用同一个值**，不等于这些数值永远不能调整。需要改时改全局来源，不给单个元素另开一台印刷机。

| 参数 | 当前基线 | 调整规则 |
| --- | --- | --- |
| 纸色 | `#f0ebdf` | 共享纸色来源 |
| 蓝墨 / 主墨 / b | `#283eb5` | 全页同一色值 |
| 朱红 / 第二墨 / a | `#cf5037` | 全页同一色值 |
| 蓝网角 | 75° | 全局同步 |
| 朱红网角 | 15° | 全局同步；不照抄历史示例中的反向命名 |
| 点形 | 两墨当前都是圆点 | 每墨只用一种形状；圆/方只能在全局改 |
| 套版偏移 | 蓝版相对朱红参考版 X +2px / Y +1px | 所有双墨对象共用；禁止元素独立偏移 |

当前渲染约定是 **a=朱红参考版，b=蓝偏移版**。不要把用户讨论中的示例代码当成反向更换墨层的指令。

`resolve()` 中的 `pageLocked` 统一解析墨色、网角、点形和套准；旧局部配方可被读取，但不得覆盖这些全局参数。叠印使用共享 multiply 逻辑；这是一种屏幕模拟，不是印厂分色文件。

## 4. 只有三档网点

| 档位 | 当前频率 | 用途 |
| --- | --- | --- |
| coarse · 字级 | `1/16em`，按实际字号取整到 CSS px | 大字姓名的表现性蓝网层；当前桌面约 8px |
| medium · 图像 | 4 CSS px | 相邻圆形底版和其他几何 |
| fine · 细网 | 2 CSS px | 浅墨底形、背景、分隔区域、人像（2026-10-14 用户调整：4px 时人脸不易辨认），以及窄屏显示级姓名 |

- 唯一频率来源是 `src/design/screen.ts` 的 `screen(level, ink)` 与 `--screen-*` tokens。不要在组件里新增 3px、5px、6px 等自由网距。
- 字级随字号变化；平网/图像用固定 CSS px。实际渲染的网距取整；当前字级与图像档相差不足 1.5 倍时复用 fine 细网，避免看似误差的第四档；由共享 `typeScreenLevel()` 按实际字号选择，不按画幅切换成实色。
- 同色、相邻或重叠的对象使用同一档。例外：人像改用 fine（`portraitScreenLevel`，`src/config/portrait-composition.ts`，构建图与实时渲染共用），背后的圆是同一块合成印版，随人像一起用 fine。
- 可以按对象调整浓度、影调和覆盖率；不能同时改变同种墨的全局角度、形状或套准。
- 当前主版本采用 AM。未来若引入 FM，须作为明确的元素类型规则并更新本文，不开启逐元素自由算法切换。
- 不要求每屏凑齐三档。网点检查视图报告实际显示的档位，实色不计入。
- 整数 CSS px 不能保证在所有设备像素比或浏览器缩放下完全无摩尔纹。缩略预览会重采样网点；检查纹理用原尺寸。

## 5. 可读性与语义底线

- 姓名必须一眼可读。按最新字号分级：≥72px 保留朱红实色底与蓝网层；窄屏姓名小于72px时采用清晰的双墨实色。1440 当前 8px 网距保持；约 16px 及以下的小字规则仍适用。不恢复旧粗网和大错位。
- 24px 以下阅读字保持单墨实色，不挂网、不加噪声或可见错版（最新修订见第 16 节）。全页模拟双墨印刷，不要求每一个字都同时上两墨。
- 装饰副本对辅助技术隐藏；真实文字只出现一次。新双墨标题沿用 `InkText` / `PrintTitle` / `PrintWord`，不复制两份可朗读的 DOM。
- 装饰不能截获点击、遮挡文字或焦点。连接 SVG 为装饰，标题、列表和真实项目链接在无 JS 的 HTML 中仍成立。
- 保留键盘操作、可见焦点、减少动态效果支持；不要用横向裁切隐藏布局溢出。
- 普通文字对比度目标至少 4.5:1，大字至少 3:1；实际纸色、网点背景和叠印处都要检查。

## 6. 共享网格与响应式

- 桌面共用 12 列，小容器共用 4 列。导航、姓名/介绍、品牌分支与 News 落在同一套列线上，不各自另开坐标系统。
- 内容层完整且有序，表现层才可以有限错位。结构错位不能代替全局油墨套准。
- **网格优先，破格保守（用户，2026-10-15，设计原则）**：行和列都遵循网格。列：元素左右边落在 12 列列线上；行：元素上下边落在 `--baseline`（8px）行线上，间距是它的倍数。**落在网格上的错落不算破格**：同一行的模块不必对齐，可以按整列、整行错开（例如 About 的 Education 比 Experience 低若干行）。破格指离开网格线，只在内容或印刷效果确有需要时使用（例如 About 标题左出血、照片右出血、研究章节色带的出血），要少、要克制，并在本文件写明理由；不为单个模块加私有偏移、侧边线或非倍数间距。
- **行的做法：Müller-Brockmann（用户，2026-10-15）**：按《Grid Systems》与网页基线网格的通行做法，不只是让上边对齐行，而是控制尺寸——所有竖向尺寸（行高、上下外边距与内边距、行间距、块高、边框）都是整行（`--baseline`，8px）。这样每个模块的高度是整行，下一个模块的上边自然落在行线上。图片占整行的格子（field），可见边缘向内缩进正文的半行距（`(行高 - 字号) / 2`；Newsreader 的 ascent + descent 正好 1em），因此图片上边与旁边第一行文字的升部齐、下边与最后一行的降部齐。以后文字多的详情页改用 Lupton 的基线对齐（图片下边落在基线上）。
  - 实现：`scripts/rhythm.mjs`（PostCSS，`postcss.config.mjs`）在构建时把站点样式里的行高、竖向间距和块高取整到行；作者照常写比例和数值。横线用整像素，宽度从下方外边距里还回去，顶线从其下的内边距里扣除，所以线压在行线上、内容仍从行开始。`src/styles/rhythm.css` 处理高度随宽度变化的盒子（肖像、About 照片、Print Labs 叠片、研究圆，用容器宽度算高度再取整行）、浏览器默认的列表外边距，以及原先居中对齐的地方（居中在非偶数行的盒子里会落在两行之间，改为对齐行线）。
  - 检查：1440、1024 的两种模式和 390/375/320 手机上，所有在流中的块级元素上边都在行线上（±0.75px）；唯一例外是同一行里按基线对齐的小字（News 日期），按基线对齐本身就是 Müller-Brockmann 的要求。
  - 局部关闭：在声明后写注释 `rhythm:off`。
- **分隔线只有一套（用户，2026-10-15）**：页面大标题下不加线（Home、Research、Artifacts 一致）；模块标题下不加线；About 后续模块（Funding、Reviewing、Outside research、Contact）统一用一条 2px 蓝墨顶线分隔，不用侧边线、收尾线或朱红线；Artifacts 单件作品不加侧边线。研究项目之间的底线、首页的章节线与 News 色带保持原样。
- 当前 Home 的间距参数为 56px，品牌字号参数为 56px；这是可调基线，实际显示字号遵循响应式规则。
- News 在所有宽度使用单栏时间流，日期与正文分列；没有装饰圆圈和重复日期短条。已知日期按月/年展示；只有年份的记录保留年份，不编造月份。
- 断点取决于页面容器，不要把浏览器宽度与内容宽度混为一谈。测试至少覆盖 1440、768、375、320px，并在涉及断点变化时查看中间尺寸。

## 7. 设计台、独立预览与发布必须同源

- 首页和设计台共用组件、CSS、参数解析与素材管线。不能用设计台专属 DOM 改写来做一套正式页面没有的构图。
- **设计台和独立预览默认都用同一张 1440px 主版画布**，窗口变窄时只缩小展示，不偷偷切换断点。整幅 / 原尺寸切换只改变查看方式；1440 原尺寸用于网点检查。
- 其他尺寸明确归为「适配检查」，不能覆盖主版默认画幅。真实网站仍按浏览器宽度响应式排版，不给手机访客强制缩小一整张桌面页。
- 「独立预览 1440 主版」必须带入当前会话草稿，不能悄悄改用已保存配置。未保存的预览要标明状态；保存才更新 `src/config/design.json`。
- `/design/?view=preview` 是同一设计台隐藏控制面板后的独立画布，仍使用当前会话草稿和 1440 主版；不要另建一套预览组件。直接访问 `/` 使用已保存的响应式网站。旧的 `/?design-preview=current` 仍可作为响应式草稿检查入口，不是主版独立预览。
- 比较效果时先对齐配置、实际排版宽度、缩放与设备像素比，并关闭网格/网点诊断/单墨分版。缩小后的网点观感不能用来判断素材管线是否不同。
- 检查视图、编辑面板、保存接口和草稿逻辑不得进入发布产物。

相关实现：`src/design/preview-state.ts`、`src/client/studio.ts`、`src/client/preview.ts`、`scripts/design-server.ts`。

## 9. 每次调整的落地方式

1. 先读本文，确认改动属于全局规则、可调基线、单个元素还是公开内容。
2. 改共享来源；不要新建另一套实验首页来绕过主版本。
3. 用同一配置、同一宽度核对设计台与独立预览。涉及网点时检查单墨与档位视图，涉及文字时检查窄屏与重复朗读。
4. 运行与改动有关的检查。代码改动使用现有测试、`npm run check` 和构建验证；保存接口改变时运行 `npm run test:server`。仅文档修改不需要重跑整站。
5. 用户改变全局规则时，同步本文、对应 token/实现和必要测试；交接文档只记录过程，不取代本约束文档。

代码已强制的部分包括参数范围/作用域、全局物理参数、三档频率、已选方案收敛和发布隔离。视觉焦点、文案确认、对比度与响应式观感仍需人工审阅；测试通过不代表所有设计约束自动验收。

## 10. 首页分隔与动态（2026-10-14）

- 当前分隔处理为个人介绍 → 研究的双墨章节线，以及研究 → News 的 4 行（32px）fine 细网过渡带。News 标题不再用纸色方块挡住色带：色带从标题下穿过，标题双墨与色带叠印（multiply，参照 Element Lab 的叠加运算，用户 2026-10-15）；条目正文保持干净纸面与单墨细线。
- 章节线共用全页墨色与套准；News 网带共用 fine 频率、蓝版网角、点形和材质管线。过渡带默认墨量 .18，可调 .08–.30，不以透明度替代网点。
- 两版首次进入视口时用遮罩印出，持续 700ms，蓝版延迟 110ms。动画不拉伸网点、不改变套准；减少动态效果、无 JS、打印与高对比度环境均保留完整内容。印出动态是共享分隔规则，不应用于正文。
- 设计台在现有主版本内提供「双墨章节线 + News 细网过渡 / 原细线对照」及全局静态/首次印出控制；不新建平行首页。正式页面、设计台与独立预览读取相同配置。
- 全局约束允许调整；调整必须同步共享来源和所有受影响对象，不能为单个分隔私设墨色、网角或套准。本轮不引入日期随机变化。

## 17. 页面噪声坐标与原版对照（2026-10-14）

- 新活动材质采用 `onSheet(press, globalSeed, origin, pageHeight)`。文字低频墨量、色带/几何与运行时人像转印读取同一纸张坐标场；元素标识、字号及裁切尺寸不再改变这张场。坐标按 CSS px，设计台缩放须还原，滚动不改变纹理。
- `sheet.ts` 的活动加网只分配 w×h；DPR≥2时允许原版规则的随机二值扩张，DPR<2不扩张。不经过 boxBlur，不用于文字；文字继续遵守第16节。
- **细网防故障（2026-10-14）**：一格网点跨越的设备像素少于 `minBinaryCell`（6）时，单像素二值采样无法表示点间空隙，会形成随机 1px 孔洞与斑块。此时同一 AM 点阵改为每像素 4×4 子采样的面积覆盖率，并且不做随机扩张；网角、点形、频率与平均墨量不变。≥6 设备像素的网格保持原版二值加网与扩张，原版对照测试不变。当前受影响的是 fine 2px（任意 DPR）与 1× 屏上的 medium 4px；2× 构建人像不变。`tests/screen-glitch.test.mjs` 要求均匀墨量在 1×/2× 下 8px 块覆盖率标准差 ≤.02、两种 DPR 平均墨量差 ≤.03；以后任何噪声或加网改动不得让它失败。
- **细网与设备无关（2026-10-14）**：fine 档（2 CSS px）在任何 DPR 下都按面积覆盖率解析（`minBinaryPitch`=3 CSS px）。此前 DPR 3 手机上一格正好 6 设备像素，切换为二值点加随机扩张，章节色带读作闪烁的白点（用户反馈“花眼”）；电脑上却是均匀细网。现在同一 CSS 网点在所有设备上看起来一致；medium/coarse 档在 ≥6 设备像素时仍保留原版二值点。
- 保留旧 `material-v1` 未绑定sheet的路径仅用于旧基准及历史兼容。静态后备现在使用 sheet 绑定的共享核心、固定参考布局；不能宣称与任意响应式页面噪声逐像素一致，不新增淡入。
- 研究圆的墨量、纤维及已有走纸调制也在页面坐标采样，强度、点形和交互保留自身配方；静态后备也使用共享 sheet 场。20段滚筒 rows 已恢复，按页面高度和 Y 采样；完整 mono/sep/duo/tri 分色已集中到 sources.ts，已选照片仍保留 percentile 配方。人像和几何插图构建/浏览器共用核心，SVG 墨纹后备已删除。全局纸纹与墨的进一步物理交互仍不在本次范围。
- 对照测试有两个明确边界：原版 AM加网/无噪声转印（mono/duo/tri，乘色与不透明）通道误差≤1；相同随机场下矩形二值扩张与原版逐值相等。另测跨元素裁切的转印完全相同、DPR与小字规则。不同分色、不同噪声域的整页不应要求原版render零误差。

## 27. 渲染性能（2026-10-15）

- **计算放到后台线程**：文字纹理、色带网点和几何插图的逐像素印刷在 Web Worker 里算（`src/client/print-worker.ts`、`print-jobs.ts`、核心 `print-pipeline/jobs.ts`）。主线程只负责测量版面和挂结果，算多久都不卡点击和滚动。任务按优先级排队：插图（印好前是纸色）> 色带 > 文字纹理（文字已经是最终墨色）。浏览器不支持 Worker 时在主线程计算，结果相同。
- **先读后写**：每一遍渲染先一次性读完所有尺寸、样式和纸面坐标，再统一写入，避免反复强制重排（这一项原来占了好几秒）。
- **遮罩用 JS 编码 PNG**（`print-pipeline/png.ts`），不再用 canvas `toBlob`/`toDataURL`，那会在主线程上同步读回 GPU 像素。
- **实心文字的纹理按 2 CSS px 采样**，再由 CSS 放大：文字只有低频墨量变化，1px 细颗粒面积不到 4%、减墨不到 8%，放大后看不出区别。网点色带和网点字仍按设备像素计算。
- **运行时快速路径（`Press.fast`）**：fine 网点仍是同样的 4×4 点采样，但用角度递推代替每个采样点的两次 cos，结果只差浮点舍入；转印的低频场（缺墨、滚筒）按 2 CSS px 网格采样后插值，细颗粒仍逐像素。迁移基准走精确路径，保持不变；`tests/fast-path.test.mjs` 保证快速路径与精确路径的墨量差 ≤.012、8px 块差 ≤.03。
- **噪声格点哈希改为数值计算**，与原来基于字符串的 `rng(salt(seed,"x:y"))` 逐值相同（`tests/lattice.test.mjs`）。
- **调度**：版面类工作用 `setTimeout` 合并触发，不用 `requestAnimationFrame`（不在出帧时不会执行）；页面高度不再触发重印；开机时的分区接管不算“导航中”，不会推迟印刷。
- 测量结果（2 核云服务器上的无界面浏览器，比普通电脑慢）：电脑高清屏主线程总占用由约 9.7 秒降到约 1.5 秒，最长卡顿由 2.3 秒降到约 0.55 秒；手机 3 倍屏由约 6.0 秒、1.1 秒降到约 0.9 秒、0.35 秒。印刷全部完成仍需几秒，其中较大一段是该环境软件光栅化的合成等待，需在真机上复测。

管线的图解（每一步的真实中间结果、元素对照表、运行时顺序、文件地图）见 `docs/pipeline.html`；图像由 `scripts/render-pipeline-doc.mjs` 生成，管线改动后重新运行。

## 2026-10-16 统一实际工序，不只统一入口

当前页面的工序为：原稿/分色与影调 → 网版几何 → `transferPlate` → 共享套准 → 输出后端合成/挂载。

- `sheet-context.ts` 只提供共同纸面坐标和 seeded 场；`sheet.ts` / `text.ts` / `polygon.ts` / `line-screen.ts` 负责加网，不计算着墨噪声。
- `transfer.ts` 的 `transferPlate` 是实际工艺分发入口，处理 raster、text、polygon、line、rule、name-dots、insert。原先分散的缺墨、颗粒、滚筒、线条边缘损失和名字网点墨量计算已迁入此模块；不是加一个空的 wrapper。栅格配方返回强度采样器，矢量配方返回转印后的墨点或轮廓，文字配方返回 alpha；这些是同一工序的输出适配，不能在宿主再加第二遍噪声。
- `registration.ts` 为 Canvas/SVG 提供同一仿射框架，为栅格提供统一偏移计算；`raster-composite.ts` / `browser.ts` / `vector.ts` 只合成与输出，不生成着墨噪声。
- 工艺与配方分离：照片、标题、线网仍用已批准的强度/限幅和几何表示，不能为了让实现看起来一样而把线网换成圆点或二次栅格化小字。扩墨全局关闭。
- 原色 Artifacts 和已印好的品牌原稿用 insert 配方：明确通过恒等转印，保留原稿，不重复加网。正文的无材质配方也不能擅自增加效果。
- 发布构建只生成当前在用的人像合成与 About 图片。历史 print/portrait-flow 工具不再被发布构建调用；保留历史源文件供研究，不代表它们是可供新元素选用的旁路。
- `tests/unified-stages.test.mjs` 检查每类在用适配器调用实际 Transfer，并禁止加网/输出模块调用着墨噪声。迁移前捕获的 `pipeline-pre-unification-20261016.json` 覆盖当前输出，迁移后逐项完全相等；旧历史基准不重录。
